NOTES TO ME VS. COPY FOR A READER
Every string value in config.js is rendered to the public site. There is no
private field. Notes written to me rather than to a reader — decision logs
("Decision (12 March 2027): staying with the illustrative images for now"),
priority notes ("not urgent", "worth revisiting at some point"), research
status ("no source found yet", "pending real data"), references to markers
or to config.js/bake.js — must go in a /* TODO (Brad): ... */ code comment,
never in a note/p/lead/FAQ/meta string.

A `note` block is for reader-facing sourcing and caveats only: real
citations, provenance a reader benefits from, "re-check this before relying
on it". If you're unsure which a given sentence is, ask whether someone with
the problem this page describes would care. If not, it's a comment.

`node bake.js --check` enforces this and will fail the build. The patterns
are narrow on purpose — if one fires on copy you believe is legitimately
reader-facing, reword the copy or tell me, but do not loosen the pattern.
